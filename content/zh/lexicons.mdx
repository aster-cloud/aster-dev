# 词法表

**词法表**（lexicon）是一个语言包——一种人类语言的关键词集、标点与规范化规则。Aster
的核心语法与语言无关；词法表把它映射到 English、中文、Deutsch、हिन्दी 等。所有词法表
共享同一套 **Lexicon SPI** 契约，因此任何语言写的策略都编译到同一核心。

## 工作原理

同一条规则，两种词法表，同一编译结果：

```aster
Module Pricing.

Rule discountedPrice given amount as Int, produce Int:
  If amount greater than 100
    Return amount times 90 divided by 100.
  Return amount.
```

```aster
模块 定价。

规则 折扣价格 给定 金额 作为 整数，产出 整数：
  如果 金额 大于 100
    返回 金额 乘以 90 除以 100。
  返回 金额。
```

编译器通过 `locale` / `lexicon` 参数得知用哪套词法表。它在降到中间表示前，把本地化关键词
规范化回核心语法——这就是为什么中文策略和它的英文译本产生逐字节相同的决策。

## 编写词法表

词法表是纯数据 + 一个 SPI 注册——无需改编译器。你提供：

- 关键词翻译（每个 `SemanticTokenKind` 一条，键集须与 `en-US` 骨架一致），
- 标点（语句结束符，如 `.` 或天城文 danda `।`），
- 空白模式（如 `ENGLISH` 与 `CHINESE` 分词）。

核心负责规范化与降级。语法契约见[参考手册](/docs/reference)，在[演练场](/playground)
试试非英文源码。

## 关键词别名

一个词法表可以为**同一个关键词接受多种拼写**。别名只存在于**识别侧**：规范化器
会先把它改写成规范拼写，下游看到的完全一样——所以用别名写的源码与用规范拼写写的
源码降到同一份 Core IR，求值结果也一致。

别名是可选的。内置的 `en-US` / `zh-CN` / `de-DE` / `hi-IN` 都**不带**任何别名，
需要时由你按团队习惯添加：

```ts
import { EN_US } from '@aster-cloud/aster-lang-ts/lexicons/en-US';

// 让这个团队可以用 `Yield` 代替 `Return`
const teamLexicon = { ...EN_US, aliases: { RETURN: ['Yield'] } };

compile(source, { lexicon: teamLexicon });
```

三条关键性质：

- **规范拼写继续可用**。注册 `Yield` 不会让 `Return` 失效，两者都能编译。
- **IR 不变**。只有源码位置会变（别名与规范拼写长度不同会让列号平移），
  语义树与求值结果完全一致。
- **不注册就只是个不认识的词**，编译失败。别名不会跨词法表泄漏。

正因为别名在降级前就折叠掉了，它没有任何运行期开销，也不可能改变决策结果——
这才使得把它交给非工程师是安全的。

## 领域词汇

词法表翻译的是**关键词**；**领域词汇**翻译的是**标识符**——结构体名、字段名、
函数与枚举值——好让规则能用业务真正在说的词来写。

每条术语把稳定的 `canonical` 名与 `localized` 拼写配成一对：

```ts
import { vocabularyRegistry } from '@aster-cloud/aster-lang-ts/lexicons/identifiers/registry';
import { IdentifierKind } from '@aster-cloud/aster-lang-ts/lexicons/identifiers/types';

vocabularyRegistry.registerCustom('acme-tenant', {
  id: 'lending', name: 'lending', locale: 'en-US', version: '1',
  structs: [{ canonical: 'Applicant', localized: 'Borrower', kind: IdentifierKind.STRUCT }],
  fields: [{ canonical: 'score', localized: 'creditScore',
             kind: IdentifierKind.FIELD, parent: 'Applicant' }],
  functions: [], enumValues: [],
});

compile(source, { lexicon: EN_US, domain: 'lending', tenantId: 'acme-tenant' });
```

规则随即可以用该领域的词来写：

```aster
Module lend.

Define Borrower has
  creditScore as Int.

Rule decide given who as Borrower, produce Text:
  If who.creditScore at least 680:
    Return "APPROVED".
  Return "REFER".
```

### 求值输入用的是 canonical 名

这一条几乎人人都会踩。**源码**用 localized 词书写，但 `evaluate` 收发的是
**canonical** 名——因为编译产物 IR 里存的就是 canonical：

```ts
evaluate(core, 'decide', { who: { score: 700 } });      // ✅ canonical
evaluate(core, 'decide', { who: { creditScore: 700 } }); // ❌ 找不到该字段
```

术语还可带 `aliases`（同一标识符的其它拼写）与 `description`，二者均可选；
标识符别名与关键词别名一样，也只作用于识别侧。

### 字面量宏：把术语展开成固定文案

第五个集合 `literals` 与前四个不同：它不是给标识符改名，而是把一个术语展开成
**固定的字符串**——适用于监管文案必须逐字出现、不能靠人手抄写的场景。

注意这里的反转：对 `IdentifierKind.LITERAL` 而言，`canonical` **不是**标识符，
而是要替换出去的**字符串内容**（不含引号）。

```ts
vocabularyRegistry.registerCustom('acme-tenant', {
  id: 'poem', name: 'poem', locale: 'en-US', version: '1',
  structs: [], fields: [], functions: [], enumValues: [],
  literals: [{ canonical: '静夜思', localized: '思故乡',
               kind: IdentifierKind.LITERAL }],
});
```

编译时要传入与注册时相同的 `domain` + `tenantId`——两者缺一，词汇表就不会被查询，
触发词只会被当成未知名字：

```ts
compile(source, { lexicon: EN_US, domain: 'poem', tenantId: 'acme-tenant' });
```

之后触发词就代表那段文案：

```aster
Module poem_demo.

Rule title produce Text:
  Return 思故乡.
```

求值 `title` 得到 `"静夜思"`。

若漏传其中任一项，`compile` 仍然报成功，失败要到求值时才以
`Undefined variable '思故乡'` 的形式冒出来——这个报错看着像拼写错误，
而不是"少传了参数"。遇到它请先检查 `domain` 与 `tenantId`。

**仅限表达式位置。** 字面量宏展开成的是**字符串**，所以把触发词用在需要名字的地方
——规则名、字段名、结构体名——会编译报错。`Rule 思故乡 produce Int:` 不能编译。

**内容受严格校验**，防止不受信租户在编译期注入源码。会被拒绝的：内容为空、
含控制字符或换行、含引号定界符或反斜杠——`"`、`\`、`「」`、`『』`、`«»`。
普通可见文本（含中日韩字符与标点）没问题，例如 `静夜思——李白` 可通过校验。

**两个引擎都**在注册时拒绝弯引号 `“ ” ‘ ’`。（aster-lang-core v1.0.27 之前 JVM
引擎在注册时放行、只在展开阶段拦截，该分叉已消除。）之所以必须早拒：
canonicalizer 会把 `“ ”` 归一化成 ASCII `"`，放行的内容在展开后会变成真正的引号——
重新编译 canonical 输出会因未闭合字符串而失败，即**展开不幂等**。

字面量条数与单条展开长度**都没有上限**——「严格校验」指的是上面的字符规则，
不含体量限制（实测单条 5 万字符、5000 条词条均通过）。若这部分内容由租户提供，
请自行设限。

**触发词必须全局唯一。** 字面量宏的 `localized`（及其 aliases）不得与**任何**
其它映射（含普通标识符）同名。因为替换是上下文无关的，同名会导致同一个词
在一处展开成字符串、在另一处展开成标识符，不可预测。

`parent` 对字面量宏**不适用**——传了不会报错也不会警告，直接被忽略，
不要指望用它做作用域限定。

`aliases` 在这里同样生效：每个别名都是一个额外的触发词，展开成同一段文案。
但展开是**单向的**——与其余四类不同，字面量宏不建反向映射，
所以把已是 canonical 的源码本地化回去时，那段文案不会变回触发词。

### 为什么要分成两套机制

关键词别名与领域词汇看着相似，但刻意分开：关键词属于**语言**本身、来自受信的
词法表；标识符属于**租户**、在运行期按租户注册。正是这条分界让不受信的租户能
提供自己的词汇，却无法重新定义语法。

`/demos` 下的页面就是可运行的实例——猫咪心情 demo 用一整套「撸猫术语」写成的规则
真编译真执行，底层与信贷 demo 是同一套引擎。
