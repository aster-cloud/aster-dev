# 标准库

Aster 内置的函数。全部是**确定性的**，在两套引擎（TypeScript 与 JVM）上运行结果一致。用括号调用，例如 `List.sum(xs)`。下面每个示例都按原样可编译、可运行。

> 确定性：这里刻意**没有** `today()` / `now()` / `random()`。当前日期作为输入传入（见 `Date.*`）。正是这一点让决策可回放、两套引擎字节级一致。

## Text（文本）

| 函数 | 签名 | 结果 |
| --- | --- | --- |
| `Text.concat(a, b)` | `(Text, Text) → Text` | `a` 后接 `b`（也可直接用 `a plus b`） |
| `Text.toUpper(t)` | `(Text) → Text` | 转大写 |
| `Text.toLower(t)` | `(Text) → Text` | 转小写 |
| `Text.length(t)` | `(Text) → Int` | 字符数 |
| `Text.equals(a, b)` | `(Text, Text) → Bool` | 两侧先转成文本再判等 |
| `Text.contains(haystack, needle)` | `(Text, Text) → Bool` | 子串测试 |
| `Text.startsWith(t, prefix)` | `(Text, Text) → Bool` | 前缀测试 |
| `Text.indexOf(t, sub)` | `(Text, Text) → Int` | 首次出现的下标，否则 `-1` |
| `Text.split(t, delimiter)` | `(Text, Text) → List` | 拆分为列表 |
| `Text.trim(t)` | `(Text) → Text` | 去除首尾空白 |
| `Text.substring(t, start[, end])` | `(Text, Int[, Int]) → Text` | 切片 `[start, end)` |
| `Text.replace(t, target, replacement)` | `(Text, Text, Text) → Text` | 替换全部出现处（字面量，非正则） |

```aster
Module text_demo.

Rule shout given name as Text, produce Text:
  Return Text.toUpper(name) plus "!".
```

`Text.equals` 与 `is equal to` 运算符**并不等价**。它会先把两个参数转成文本，
因此 `Text.equals(5, "5")` 为 `True`，而 `5 is equal to "5"` 不是。
两个引擎的转换行为一致，所以结果是确定的——但如果要比较的本来就是 `Text`，
更推荐用 `is equal to`：它会让类型不匹配暴露出来，而不是被静默转成字符串。

## List（列表）

| 函数 | 签名 | 结果 |
| --- | --- | --- |
| `List.empty()` | `() → List` | 新建一个空列表 |
| `List.length(xs)` | `(List) → Int` | 元素个数 |
| `List.isEmpty(xs)` | `(List) → Bool` | `xs` 无元素时为 `True` |
| `List.get(xs, i)` | `(List, Int) → T` | 下标 `i` 处的元素（越界 → 报错） |
| `List.contains(xs, v)` | `(List, T) → Bool` | 成员测试 |
| `List.append(xs, v)` | `(List, T) → List` | 追加 `v` 后的新列表 |
| `List.concat(xs, ys)` | `(List, List) → List` | 连接两个列表 |
| `List.slice(xs, start[, end])` | `(List, Int[, Int]) → List` | 切片 `[start, end)` |
| `List.distinct(xs)` | `(List) → List` | 去重，保序 |
| `List.range(start, end)` | `(Int, Int) → List` | 整数 `[start, end)` |
| `List.sum(xs)` | `(List) → Num` | 求和（空 → 0） |
| `List.min(xs)` / `List.max(xs)` | `(List) → Num` | 最小 / 最大（空 → 报错） |
| `List.sort(xs)` | `(List) → List` | 升序，稳定 |
| `List.combinations(xs, k)` | `(List, Int) → List` | 全部 `k` 元组合（字典序） |

```aster
Module list_demo.

Rule total given amounts as List, produce Int:
  Return List.sum(amounts).
```

`List.combinations` 出于安全做了限制：输入至多 64 个元素，且组合数量设了上限（超大输入会报错而非卡死）。

### 高阶（lambda）列表函数

`List.map` / `List.filter` / `List.reduce` / `List.count` / `List.sortBy` / `List.minBy` / `List.maxBy` / `List.groupBy` 接受一个函数参数。把该函数定义为具名规则，按名传入。

```aster
Module hof_demo.

Rule increment given x as Int, produce Int:
  Return x plus 1.

Rule bumpAll given xs as List, produce List:
  Return List.map(xs, increment).
```

## Map（映射）

`Map` 把字符串键映射到值。所有操作都返回新映射（不可变）。

| 函数 | 签名 | 结果 |
| --- | --- | --- |
| `Map.empty()` | `() → Map` | 空映射 |
| `Map.get(m, key)` | `(Map, Text) → Maybe` | `Some(值)`，若不存在则 `None` |
| `Map.put(m, key, value)` | `(Map, Text, T) → Map` | 设置该条目后的新映射 |
| `Map.remove(m, key)` | `(Map, Text) → Map` | 移除该键后的新映射 |
| `Map.contains(m, key)` | `(Map, Text) → Bool` | 键存在测试 |
| `Map.keys(m)` | `(Map) → List` | 所有键 |
| `Map.values(m)` | `(Map) → List` | 所有值 |
| `Map.size(m)` | `(Map) → Int` | 条目数 |

> **破坏性变更（1.0.26 起）。** `Map.get` 现在返回 `Maybe` 而非裸值/`null`：
> 缺键是 `None`，命中是 `Some(值)`。这让「键可能不存在」在代码里**显式可见**，
> 而不是等到表达式深处才冒出一个运行期类型错误。
> 迁移：需要兜底用 `Maybe.withDefault(...)`，需要分支用 `Match ... When null`。

```aster
Module map_demo.

Rule lookup given score as Int, produce Int:
  Let table be Map.put(Map.empty(), "gold", score).
  Return Maybe.withDefault(Map.get(table, "gold"), 0).
```

若要分别处理两种情况而不是合并掉，用 `Match`。注意每个模式后面的**逗号**——
这是必需的写法：

```aster
Module map_match_demo.

Rule lookup given key as Text, produce Int:
  Let table be Map.put(Map.empty(), "gold", 7).
  Match Map.get(table, key):
    When null, Return 0.
    When Some(v), Return v.
```

## Date（日期）

日期表示为自 1970-01-01 起的整数天数（「epoch-day」）。比较或平移日期就是整数运算。没有 `today()`——把求值日期作为输入传入。

| 函数 | 签名 | 结果 |
| --- | --- | --- |
| `Date.fromISO(iso)` | `(Text) → Int` | 严格解析 `YYYY-MM-DD` → epoch-day |
| `Date.daysBetween(a, b)` | `(Int, Int) → Int` | `b - a` 的天数（可为负） |
| `Date.addDays(d, n)` | `(Int, Int) → Int` | 平移 `n` 天 |
| `Date.year(d)` / `Date.month(d)` / `Date.day(d)` | `(Int) → Int` | 提取字段 |

```aster
Module date_demo.

Rule ageInDays given birthday as Text, asOf as Text, produce Int:
  Return Date.daysBetween(Date.fromISO(birthday), Date.fromISO(asOf)).
```

错误：格式错误或超范围的日期会抛 `Date.InvalidISODate`；运算结果超出支持范围（0001-01-01 … 9999-12-31）会抛 `Date.OutOfRange`。

## Decimal（十进制）

用于金额与费率的精确十进制数。写 Decimal 字面量时加 `m` 后缀（`1.08m`）。`+`、`-`、`*` 是精确的；除法与舍入必须显式。

| 函数 | 签名 | 结果 |
| --- | --- | --- |
| `Decimal.round(x, scale, mode)` | `(Decimal, Int, Text) → Decimal` | 舍入到 `scale` 位小数 |
| `Decimal.divide(x, y, scale, mode)` | `(Decimal, Decimal, Int, Text) → Decimal` | 精确除法后舍入 |

`scale` 取 `0…18`。`mode` 为 `"HALF_UP"`、`"HALF_EVEN"`（银行家舍入）或 `"DOWN"`（截断）——与 JVM 同名的 `RoundingMode` 一致。

```aster
Module money_demo.

Rule withTax given price as Decimal, produce Decimal:
  Return Decimal.round(price times 1.08m, 2, "HALF_EVEN").
```

把 `Decimal` 与二进制浮点（`Double`）混用会在求值时被拒——请改为把 `Int` 提升为 `Decimal`。`Decimal.divide` 除以零会报错。

## Maybe / Option 与 Result

用 `Some(x)` / `None` 构造可选值，用 `Ok(x)` / `Err(e)` 构造可失败值。用下面的辅助函数（或用 `Match`）检视它们。

| 函数 | 结果 |
| --- | --- |
| `Maybe.isSome(o)` / `Maybe.isNone(o)` | `Bool` |
| `Maybe.withDefault(o, fallback)` | 值，若为 `None` 则 `fallback` |
| `Maybe.unwrapOr(o, fallback)` | 与 `withDefault` 完全相同——见下方说明 |
| `Maybe.unwrap(o)` | 值（为 `None` 时报错） |
| `Maybe.map(o, f)` | `Some(f(值))`；为 `None` 时原样返回 |
| `Result.isOk(r)` / `Result.isErr(r)` | `Bool` |
| `Result.unwrap(r)` / `Result.unwrapErr(r)` | Ok 值 / Err 值 |
| `Result.mapOk(r, f)` | `Ok(f(值))`；为 `Err` 时原样返回 |
| `Result.mapErr(r, f)` | `Err(f(错误))`；为 `Ok` 时原样返回 |
| `Result.tapError(r, f)` | 执行 `f(错误)`，返回**原样**的 `r` |

`Option.*` 别名覆盖**四个**辅助函数——`Option.isSome`、`Option.isNone`、
`Option.unwrap`、`Option.unwrapOr`——行为与对应的 `Maybe.*` 完全一致。
建议一个代码库内统一用一种写法。

别名集合**并不完整**：`Maybe.withDefault` 与 `Maybe.map` 没有在两个引擎上
都保证可用的 `Option.*` 对应物。这两个请统一用 `Maybe.*` 写法。

**`Maybe.unwrapOr` 与 `Maybe.withDefault` 行为完全相同**——参数个数相同、结果相同，
`None` 时都返回 `fallback`。保留两种写法是为了照顾不同背景的读者
（`unwrapOr` 对 Rust 用户更自然，`withDefault` 对 Elm/OCaml 用户更自然）。
两者皆可，本文示例统一用 `withDefault`。

`Result.tapError` 用于在不消费错误的前提下查看它。但运行时是沙箱化且确定性的，
回调**无法**记录日志或做 I/O，因此在规则内部很少有实际用途——
更推荐把 `Result` 返回给调用方应用去处理错误。

```aster
Module maybe_demo.

Rule scoreOrZero given raw as Int, produce Int:
  Let maybeScore be Some(raw).
  Return Maybe.withDefault(maybeScore, 0).
```

map 系列只改变载荷、保留外层包装——`None` 与 `Err` 会原样穿过，
这正是它们可以安全串联的原因。与 `List.map` 一样，函数参数是**具名规则，按名传入**：

```aster
Module maybe_map_demo.

Rule double given x as Int, produce Int:
  Return x times 2.

Rule doubledOrZero given raw as Int, produce Int:
  Let doubled be Maybe.map(Some(raw), double).
  Return Maybe.withDefault(doubled, 0).
```

## 不提供的能力

`Math.*` 和真正的 `IO.*`（文件/网络）**不**属于标准库——运行时按设计是沙箱化且确定性的。算术请用运算符（`plus`、`minus`、`times`、`divided by`、`modulo`）；I/O 请从你的应用调用规则、在那里做 I/O。
