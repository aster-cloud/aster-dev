# Language Reference

The authoritative reference for Aster's grammar, type system and evaluation
semantics. The [Language Guide](/docs/language-guide) is the tutorial-style
introduction; this page is the specification.

## Grammar

Aster's surface grammar is defined per-locale by a **lexicon** (keyword set) over a
shared core grammar. The English lexicon uses `Module`, `Rule`, `given`, `has`,
`Return` and `If`. Other locales translate the keywords; the core grammar and
intermediate representation are identical.

```ebnf
module      = "Module" Name "." declaration+ ;
declaration = define | rule ;
define      = "Define" Name "has" field ("," field)* "." ;
rule        = "Rule" Name "given" params ("," "produce" Type)? ":" body ;
ifStmt      = "If" condition body ;
body        = statement+ ;
statement   = ifStmt | "Return" expression "." ;
```

**A rule header is one line.** Everything from `Rule` to the `:` (or `.`) that ends
the header — parameters, `produce`, and any `It performs …` clause — must be written
on a single line. Since engines 1.0.48 / `aster-lang-ts` 3.1.0 a line break inside
the header is a parse error in both engines (typically `E055 Expected identifier`).
Rule bodies and the field list of `Define … has` may still span several lines.

```text
Rule decide given amount as Int, produce Int:      ✅ one line
Rule decide given amount as Int,
  produce Int:                                     ❌ E055
```

## Type system

Aster provides four built-in primitive types plus user-defined structs. Types are
**inferred** — you rarely write them.

### Primitive types

| Type | Description | Examples |
| --- | --- | --- |
| `Int` | Integer | `0`, `42`, `-7` |
| `Float` | Floating-point | `3.14`, `0.5`, `-1.0` |
| `Text` | String (double-quoted) | `"hello"`, `"gold"` |
| `Bool` | Boolean | `true`, `false` |

> **DateTime inference** — `DateTime` is not a keyword. The compiler infers it for
> fields whose names match temporal patterns (`createdAt`, `birthday`, `expiryDate`).

### Custom types (structs)

Any name introduced by a `Define` declaration becomes a valid type:

```aster
Module Insurance.

Define Policy has premium as Int, deductible as Int.

Rule quote given age as Int, produce Policy:
  If age is less than 25
    Return Policy with premium set to 500, deductible set to 1000.
  Return Policy with premium set to 300, deductible set to 500.
```

### Composite types

Composite types are written in words and nest freely:

| Written | Meaning | Type arguments |
| --- | --- | --- |
| `list of T` | list of `T` | exactly one |
| `option of T` | a `T` or nothing — values `Some(x)`, `None` | exactly one |
| `result of T and E` | success `T` or failure `E` — values `Ok(x)`, `Err(e)` | at most two |
| `map K to V` | map from `K` to `V` | key and value |
| `(A, B) -> R` | function taking `A` and `B`, returning `R` | parameter list and result |

```aster
Module Composite.

Rule double given x as Int, produce Int:
  Return x times 2.

Rule applyOrZero given value as option of Int, f as (Int) -> Int, produce Int:
  Return Maybe.withDefault(Maybe.map(value, f), 0).

Rule validate given amount as Int, produce result of Int and Text:
  If amount less than 0
    Return Err("negative amount").
  Return Ok(amount).
```

A function type can be the type of a parameter, so a rule can take another rule by
name: `applyOrZero(Some(4), double)` returns `8` (current release,
`aster-lang-ts` 3.3.0).

How far an `X of …` type reaches: after a separator, a `name as` pair or a token
that cannot start a type belongs to the enclosing list, so
`given r as result of Int and Text, y as Text` has two parameters. A bare lowercase
name after a separator, with no `as` (the `y` in `given x as Pair of Int, y, produce Int`),
is `E055` in both engines (`aster-lang-ts` matches core from 3.3.0; earlier ts silently
read it as another type argument); write `y as <Type>`, or parenthesise the type:
`(Pair of Int), y`. Separate the two
arguments of `result of` with `and`. Inside the parenthesised parameter list of a
function type a comma would be ambiguous — it could be the next parameter or the
failure type — so it is reported as `E064` (`Unexpected ','`); write `and`, or
parenthesise the inner type:

```text
(result of Int, Text) -> Bool       ❌ E064
(result of Int and Text) -> Bool    ✅ one parameter
((result of Int), Text) -> Bool     ✅ two parameters
```

### Signature syntax rulings (available from 1.0.49 / `aster-lang-ts` 3.2.0)

Engines 1.0.49 and `aster-lang-ts` 3.2.0 settle the remaining differences between
the two engines in parameter lists and type expressions. Both engines now behave as
follows:

| Written | Result | Write instead |
| --- | --- | --- |
| `given x as Pair<Int, Text>` | `E056` at `<` — angle-bracket type arguments are not supported | `Pair of Int and Text` |
| `given Customer as Text` | `E055` — a parameter name must not start with an uppercase A–Z letter | `customer as Text` |
| `given xs as list of Int and Text` | `E055` — `list of` takes one type, and `Text` would be an uppercase parameter name | `list of Int` |
| `given r as result of Int or Text` | `E062` at `or` | `result of Int and Text` |
| `given n as maybe of Text` | `E061` at `of` | `maybe Text` |
| `given @pii(L1, email) email as Text` | accepted: annotations before a parameter name | — |
| `Type Amount as Int.` | accepted: the `type` keyword is case-insensitive, like the other declaration keywords | — |
| `given n as maybe Text`, `maybe @pii(L1, name) Text` | accepted: `maybe T` is the prefix form of `T?` | — |

Annotations written before a parameter name and a `@pii(…)` on the outermost type
both end up in the parameter's `annotations` in Core IR, the same in both engines.

```text
Rule f given x as Pair of Int, @pii(L1, email) y as Text, produce Int:   ✅ two parameters
Rule f given r as result of Int or Text, produce Int:                   ❌ E062
```

## Control flow

Conditional logic uses `If … Return …`. Branches are evaluated top to bottom; the
first whose condition is `true` returns and stops the rule. A trailing `Return`
with no `If` is the default.

```aster
Module Grading.

Rule classify given score as Int, produce Text:
  If score is at least 90
    Return "excellent".
  If score is at least 70
    Return "good".
  If score is at least 50
    Return "average".
  Return "poor".
```

Conditions compose with `and` / `or` rather than deep indentation where possible.

## Operators

### Arithmetic

| Operator | Meaning | Example |
| --- | --- | --- |
| `plus` | addition | `amount plus 10` |
| `minus` | subtraction | `price minus discount` |
| `times` | multiplication | `quantity times unitPrice` |
| `divided by` | division | `total divided by count` |
| `modulo` | remainder | `n modulo 2` |
| `integer divided by` | truncating division | `n integer divided by 2` |

`times`, `divided by`, `modulo` and `integer divided by` bind tighter than `plus`
and `minus`.

### Comparison

| Operator | Meaning | Example |
| --- | --- | --- |
| `is greater than` | `>` | `age is greater than 18` |
| `is less than` | `<` | `score is less than 50` |
| `is at least` | `>=` | `income is at least 30000` |
| `is at most` | `<=` | `balance is at most 0` |
| `is equal to` | `==` | `tier is equal to "gold"` |

The leading `is` is optional — `score is at least 700` and `score at least 700`
compile identically. Use whichever reads clearer.

### Logical

| Operator | Meaning | Example |
| --- | --- | --- |
| `not` | NOT | `not isExpired` |
| `and` | AND | `age is at least 18 and income is at least 30000` |
| `or` | OR | `tier is equal to "gold" or tier is equal to "platinum"` |

`and` binds tighter than `or`, so `x or y and z` reads as `x or (y and z)`.

## Evaluation

A rule is a pure function of its inputs. Evaluation is **deterministic**: the same
inputs always yield the same result, and both the JVM (Truffle) and TypeScript
runtimes lower to the **same intermediate representation**, guaranteeing
byte-identical results.

That representation is **Core IR v2** (`schemaVersion: 2`; engines 1.0.46 and
later, `aster-lang-ts` 2.0 and later), defined by a single JSON Schema shared by
both engines. Every field is always present (`null`, `[]` or `false` when empty),
and every node carries its source `origin`. Optional and fallible values are
first-class nodes: the expressions `Some`, `None`, `Ok` and `Err`, and the types
`Option`, `Maybe` and `Result` (with an `ok` and an `err` type); patterns over them
are constructor patterns. The canonical serialisation (keys in code-point order, no
whitespace) is what you hash, store or send to the API — `compile()` returns it as
`coreJson`, see the [Browser API](/docs/browser-api). IR v1 is not readable any
more: recompile stored IR from its source. Every evaluation can emit a **decision trace** for replay —
which rule fired, on which inputs, to which result.

## Effects & purity

Rules are pure by default. Side effects (I/O, external calls) are declared
explicitly via effect capabilities, keeping the audit surface honest.

## Diagnostics

Every diagnostic carries a stable **code** and named parameters. The English
message is a fallback: editors and the [Playground](/playground) render the
localised text (English, 中文, Deutsch, हिन्दी) from the code, so a message never
has to be parsed.

| Range | Stage |
| --- | --- |
| `E001`–`E099` | types (`E050`–`E069` within it: lexing and parsing) |
| `E100`–`E199` | scopes and imports |
| `E200`–`E399` | effects and capabilities |
| `E400`–`E499` | PII |
| `E500`–`E599` | async |
| `E600`–`E606` | lowering to Core IR |
| `E700`–`E799`, `W7xx` | governance and Cedar export (see [Governance](/docs/governance)) |
| `E800`–`E807`, `W800`–`W801` | name resolution (see [Lexicons](/docs/lexicons#how-names-are-resolved)) |
| `E900` | an annotation repeats a named argument |
| `Wxxx` | warnings |

The full list is in the engine's error-code table
([`docs/error-codes.md`](https://github.com/aster-cloud/aster-lang-ts/blob/v3.3.0/docs/error-codes.md)).

The parse codes:

| Code | Meaning |
| --- | --- |
| `E050` | unrecognised character (including non-ASCII whitespace such as U+00A0 at the end of a line, before punctuation or on a whitespace-only line; in zh-CN the ideographic space U+3000 still counts as a space) |
| `E051` | unterminated string literal |
| `E052` | incorrect indentation (indent with 2 spaces) |
| `E053` | numeric literal out of range |
| `E054` | nesting too deep — expressions and types have a nesting limit of 64 |
| `E055` | expected a token here |
| `E056` | expected a token after the preceding construct |
| `E057` | expected a token inside a construct |
| `E058` | expected a token after a part of a construct |
| `E059` | expected the statement terminator |
| `E060` | expected a token before the highlighted one |
| `E061` | unexpected token |
| `E062` | unexpected token; lists what was expected |
| `E063` | cannot parse the syntax near a token |
| `E064` | unexpected construct (including an ambiguous comma in a type list) |
| `E065` | a construct is in the wrong position |
| `E066` | a block is empty |
| `E067` | invalid value (for example an annotation argument that is not text, a 32-bit integer or a boolean) |
| `E068` | wrong number of arguments to a built-in construct |
| `E069` | unknown name of a fixed kind |

## Multi-language

The same program can be written in English, 中文, Deutsch or हिन्दी — only the
keywords differ. All locales compile to the identical IR, so a Chinese policy and
its English translation produce byte-identical decisions. Try switching the source
language in the [Playground](/playground).

## Feature stability

Aster is in **technical preview**. Features fall into three tiers. Build on the
**Stable** tier with confidence; treat **Experimental** as subject to change.

### Stable — production-ready, dual-engine verified

These are covered by the byte-for-byte equivalence suite (both engines lower to
the same Core IR and produce identical results):

- **Declarations**: `Module`, `Rule … given … produce:`, `Define … has …`
  (structs), `Define … as one of …` (enums), typed parameters `given p as T`,
  `type X as Y` (type aliases)
- **Statements**: `Let … be …`, `Return …`, `If … / Otherwise`,
  `Match … When …` (including `When null` and constructor patterns)
- **Expressions**: field access `a.b`, struct construction `T with f set to v`,
  function calls, lambdas, `Some/None/Ok/Err`, string/number/decimal literals,
  lists
- **Operators**: all arithmetic (`plus`, `minus`, `times`, `divided by`,
  `integer divided by`, `modulo`), comparison (`less than`, `greater than`,
  `at least`, `at most`, `equals to`, `is (not) equal to`), and logical
  (`and`, `or`, `not`) — with short-circuit semantics locked
- **Standard library**: `Text.*`, `List.*` (incl. `map`/`filter`/`reduce`/
  `combinations`), `Map.*`, `Date.*`, `Decimal.*`, `Maybe`/`Option`, `Result`
  (see [Standard Library](/docs/stdlib))
- **`@entry`** annotation

### Experimental — usable, but the semantics may change

Implemented and parseable, but **not** yet locked by the equivalence suite. Fine
to explore; don't depend on the exact behaviour in production yet.

- **Workflows** (`Start … async`, `Wait for …`) — async, no deterministic golden
- **Cross-module `Use … version N`** — value-level references across modules need
  a multi-module runtime; `aster.modules.enabled` is off by default
- **Effect system** (`It performs io [Http, Sql, …]`) — compile-time capability
  inference; the capability set may grow or change
- **PII type system** (`@pii` + flow analysis) — enforced in CI, but the
  cross-runtime PII contract isn't separately frozen yet
- **Execution annotations** (`@cpu`, `@example`, `@deprecated`)

### Not yet available

`Set` (mutable reassignment), multi-argument `apply`, generics, `Math.*`, and real
`IO.*` are not part of the preview. Use `Let` bindings, `List.*` higher-order
functions, and parenthesised calls `f(x, y)` instead.
